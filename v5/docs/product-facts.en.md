# Kabin V5: Product fact-check & copy boundaries

## Positioning

Kabin Agent is an open AI Agent ecosystem serving three participating sides, built on a connecting platform: End Users requesting outcomes, Solution Builders packaging reusable execution recipes, and Capacity Providers offering bounded skills, plugins, models, SDKs, APIs or toolkits.

Kabin Agent is **not** merely chat, a standalone Agent store or a generic enterprise automation product. The user-facing promise is results; Builder owns the solution design; Provider owns a particular execution capability; Kabin discovers, composes, governs, verifies and intends to meter its usage.

## Architecture authority

References in vulementor/kabin-agent: docs/architecture/KABIN_CAPABILITY_FABRIC_NORTH_STAR.md, KABIN_CAPABILITY_CONTRACT_V0.md, KABIN_NEGOTIATION_PROTOCOL_V0.md, KABIN_CAPABILITY_FABRIC_DECISION_REGISTER.md.

Core loop: OutcomeContract → existing verified ExecutionRecipe if suitable → Discovery/Negotiation/Composition of Capacities → quote and human authorization → Kabin Core execution using Agentic/Routine → independent verification/evidence → metering and settlement only when implemented.

Important: GitHub source is an **untrusted candidate**, not a production-ready skill auto-installed by browsing the repo. Trust depends on provenance, license, contract, sandbox, test and admission evidence.

## Public availability boundary

The V5 website is a static HTML design/prototype. Search/filter operates only on six illustrative category cards. The intent input only shows a local example execution plan. The Solutions switcher only changes an explanatory diagram. The Provider form opens a prefilled mailto message. There is no connected AI backend, authenticated console, self-service Builder, live Provider registration, catalog inventory, billing, checkout, payout or production API on these pages.
